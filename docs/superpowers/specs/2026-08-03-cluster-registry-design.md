# Cluster registry: `cluster_registered/<cluster>_cluster_info.yml`

Date: 2026-08-03
Status: approved

## Problem

A successful provision leaves its useful output scattered: node addresses only
in the gitignored ansible inventory, ssh access only in
`~/.forgelab/ssh_config.d/`, and the installed component versions only in the
role defaults you have to go read. Nothing in the working copy answers "which
clusters exist right now, what is in them, and how do I ssh in".

## Solution

Provision writes one YAML file per live cluster into a tracked, top-level
`cluster_registered/` directory. Deprovision deletes it. The directory is the
lab's registry of live clusters: `git status` shows what changed, and the file
carries everything needed to reach the cluster.

The file is written into the working copy only. The pipeline never commits and
never pushes — no push credentials on the agent, no plan re-triggering itself.
Recording a provision in history is a manual `git add`/`git commit`. The PROV
job also publishes the file as a build artifact so the information is readable
from the build result without a checkout.

## File format

```yaml
# Generated by lab/provisioncluster/scripts/provision.py. Do not edit.
# Rewritten on every provision; removed on deprovision.
cluster: lab1
type: k8s
provisioned_at: 2026-08-03T14:22:11Z
ssh:
  user: ubuntu
  key: ~/.forgelab/id_ed25519
  example: ssh lab1-mgmt-1
nodes:
  - name: lab1-mgmt-1
    role: mgmt
    ip: 192.168.252.10
    cpu: 2
    mem: 4G
    disk: 20G
  - name: lab1-compute-1
    role: compute
    ip: 192.168.252.11
    cpu: 2
    mem: 3G
    disk: 20G
components:
  - name: kubernetes
    version: "1.30"
  - name: containerd
  - name: flannel
    version: latest
```

Every value is a fact the host already has when the run finishes:

| field        | source                                                        |
| ------------ | ------------------------------------------------------------- |
| nodes name/ip| the rendered ansible inventory (`inventory.parse_hosts`)       |
| node role    | the node's own name (`<cluster>-<role>-<n>`)                   |
| cpu/mem/disk | the resolved tfvars, keyed `<role>_cpu` / `_mem` / `_disk`     |
| components   | JSON report written by the ansible run (below)                |
| ssh          | `forgelab.paths.SSH_KEY` and the first node's name            |

No extra ssh round-trips: the file records what the lab asked for and what
ansible says it installed, not a re-interrogation of the running cluster.

## Component reporting

Each role declares what it installed; nothing in Python knows the component
list. At the end of its `tasks/main.yml` a role appends to a fact:

```yaml
- name: Report installed components
  ansible.builtin.set_fact:
    forgelab_components: "{{ forgelab_components | default([]) + [
      {'name': 'kubernetes', 'version': k8s_version},
      {'name': 'containerd'},
      {'name': 'flannel', 'version': 'latest'}] }}"
```

A final play in `site.yml` writes the collected list, as JSON, to the path
passed in `component_report`:

```yaml
- name: Record installed components
  hosts: mgmt[0]
  gather_facts: false
  become: false
  tasks:
    - name: Write the component report for the provision script
      ansible.builtin.copy:
        content: "{{ forgelab_components | default([]) | to_nice_json }}\n"
        dest: "{{ component_report }}"
        mode: "0644"
      delegate_to: localhost
      when: component_report | default('') | length > 0
```

`provision.py` creates the report path in a temp directory, passes it with
`-e component_report=...`, and reads it back. A missing or empty report is not
fatal — it renders `components: []`.

Adding a splunk role later means adding its `set_fact` block. No Python change,
no drift between what ansible installed and what the file claims.

`version` is omitted for anything the lab does not pin (containerd is whatever
the distro ships), rather than inventing a version string.

## Components and boundaries

New module `forgelab/registry.py` — the only code that knows the registry file
format. Shared, because both PROV and DEPROV use it.

| function                                   | responsibility                       |
| ------------------------------------------ | ------------------------------------ |
| `path(cluster)`                            | the file's location                  |
| `nodes_from(hosts, sizing)`                | pure: inventory hosts + tfvars → nodes |
| `read_components(path)`                    | the ansible JSON report, `[]` if absent |
| `render(cluster, type, at, nodes, comps)`  | pure: → YAML text                    |
| `write(...)` / `remove(cluster)`           | the two side effects                 |

YAML is hand-rendered — the host agent has no venv, so `forgelab` stays
standard-library only. A scalar is quoted when leaving it bare would change its
type or break the parse (numbers, `true`/`null` words, YAML indicator
characters); `1.30` becomes `"1.30"`, `192.168.252.10` and `4G` stay bare.

`paths.py` gains `REPO_ROOT` (derived from `SHARED_DIR`, like every other path
in that module) and `REGISTRY_DIR`.

`tfvars.py` gains a generic `parse(text) -> dict` for the `key = value` lines;
`parse_cluster_type` becomes a lookup on it.

## Data flow

```
provision.py
  1 validate  2 terraform apply  3 render inventory + ssh config
  4 ansible-playbook -e component_report=<tmp>/components.json
  5 verify.py                     <- fails here: no file written
  6 registry.write(...)           -> cluster_registered/lab1_cluster_info.yml

deprovision.py
  ... terraform destroy, backend sweep, drop inventory + ssh config
  registry.remove(cluster)        -> file deleted from the working copy
```

Registration is the last stage, after verify passes, so the registry only ever
lists clusters that came up healthy.

## Error handling

- Verify fails → `provision.py` exits before stage 6; no file, no stale entry.
- Ansible report missing/unparseable → `components: []`, provision still
  succeeds. The cluster is up; the manifest is just thinner.
- Re-provisioning an existing cluster name is already refused at stage 1, so a
  registry file is only ever overwritten by a run that first tore the old
  cluster down.
- `remove` tolerates an already-missing file, matching the existing inventory
  and ssh-config cleanup.
- A file left behind by VMs deleted outside the pipeline is accepted: the
  registry reflects provisions, and `make deprovision` is the way to retire one.

## Testing

`src/test/python/test_registry.py`:

- `render` output for a k8s cluster, exact (golden string)
- quoting: `1.30` quoted, `192.168.252.10` and `4G` bare, a `true`-looking value quoted
- optional round-trip through PyYAML, skipped when it is not installed
  (`pytest.importorskip`) — the golden test is the one that always runs
- `nodes_from`: role from the node name, sizing from tfvars keys, missing
  sizing keys omitted rather than rendered empty
- `read_components`: missing file → `[]`
- `remove`: existing file deleted, missing file tolerated

Extensions to existing tests:

- `test_provision.py`: the registry file exists after a successful run, is
  written after verify, and `-e component_report=` reaches ansible
- `test_deprovision.py`: the registry file is deleted
- `test_tfvars.py`: `parse` returns every key; `parse_cluster_type` still works

## Repository changes

- `cluster_registered/` at the repo root, with a `.gitkeep` and a short
  `README.md` saying the files are generated and how they get there
- `CLAUDE.md` layout map: name the directory as generated output owned by
  PROV/DEPROV, since it sits outside `lab/`
- `lab/README.md`: `registry.py` row in the forgelab module table
- `ProvisionClusterSpec`: artifact definition for
  `cluster_registered/*_cluster_info.yml`

## Out of scope

- Committing or pushing the file from CI
- Querying the live cluster for real versions (`kubectl version` and friends)
- An aggregated index of all clusters — the directory listing is the index
